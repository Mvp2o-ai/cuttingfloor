On the 3rd, 9th and 27th tool error in a row (a success starts the count again), the error offers support.contact: it's not the assistant's fault, and cuttingfloor wants to hear the tooling change that would have made it work, improved the experience, or given it the context to decide more efficiently. support.contact takes that as improvement, and the admin API returns it with each message.
